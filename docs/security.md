# 安全实现与剩余风险

本文说明当前代码实际做了什么。它不是安全认证，也不表示网站绝对安全。

## 已实现

- 密码由 Supabase Auth 使用 bcrypt 保存。应用不保存明文密码，也不把密码、验证码答案或令牌写入审计日志。
- 客户自行注册只能成为客户。管理员由 `npm run create-admin` 使用环境变量创建，源码里没有默认密码。
- 注册和登录都先校验服务端图形验证码。答案以 HMAC 存在数据库，图片接口只返回图片和不透明挑战 ID。验证码绑定 httpOnly Cookie 和用途，五分钟过期，提交一次后失效，刷新会使旧挑战失效。
- 登录、注册和验证码生成的频率限制存在 Postgres，跨 Vercel 实例有效。
- 公开注册在 Supabase 配置中应关闭。应用只在验证码通过后用 service role 调用 `admin.createUser`。
- Custom Access Token hook 对密码登录要求一次性、未过期的登录许可，并允许 `token_refresh`。恢复、魔法链接、验证码和自助注册方式会被拒绝。
- 退出登录会记录 JWT 的 session id。修改密码或撤销其他会话会更新 `tokens_valid_after`。后续请求同时检查这两项，避免访问令牌在刷新令牌作废后仍然可用。
- 客户只能读取自己的询价、报价和附件。成本价、利润和内部备注不进入客户查询列。
- 报价金额由服务端重算。已保存报价由数据库触发器禁止更新和删除。
- 已发布运价只能改为过期、被替代或归档，商业字段不能再改。
- 上传文件检查 PDF、PNG、JPEG、WebP 文件头，单文件 8 MB，最多 5 个，存放在私有桶。
- 变更接口检查来源主机，Cookie 使用 HttpOnly、SameSite=Lax。私人页面和接口设置 `Cache-Control: private, no-store`。

## 剩余风险

- 访问令牌钩子运行在密码校验之后。攻击者已经知道密码时，缺少登录许可会得到与密码错误不同的 403。这不能替代频率限制，也不能防止已经掌握密码的人在合法登录的约 20 秒窗口内重放。
- 本应用的图形验证码不是 Supabase 原生的 Turnstile 或 hCaptcha。平台不会自动执行它。生产环境应另外启用 Supabase Auth 的验证码和频率限制。
- 匿名密钥即使不进入浏览器包，泄漏后也不是机密。敏感表不应授予 anon 或 authenticated 角色。
- 第一阶段没有多因素认证，也没有安全的密码找回。未验证邮箱不能用来重置密码。
- 询价行先写入，附件上传失败时询价可能已经存在，接口仍返回文件被拒绝。
- 法律条款、费用说明和汇率来源仍需业务确认。占位文案不能当作已审核的法律文本。
